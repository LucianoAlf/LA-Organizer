## Links de sistemas via TOM — feature nova (~20h BRT)

Objetivo: o time esquece os endereços dos sistemas internos e pergunta toda hora; o TOM passa a responder o link quando perguntarem, sem nunca expor as outras ~45 credenciais (senhas, API keys) da mesma tabela.

**Decisões de desenho** (spec em `docs/superpowers/specs/2026-08-07-links-sistemas-tom-design.md`):
- Mesma tabela `governance_credentials` + coluna `visivel_tom` (default `false`), em vez de tabela separada.
- Acesso via RPC SQL `get_credenciais_publicas()`, que expõe **só** `nome` e `url_ref`. O contrato de colunas mora no schema — ampliar o que vaza exige migration, não uma linha de `.select()` em JS.
- `revoke execute` de `anon`/`authenticated`: a anon key está no bundle público do PWA; sem isso qualquer um na internet enumeraria os sistemas internos.
- Gatilho por **marker `<<PEDIR_CREDENCIAIS>>` em two-pass** (o modelo decide semanticamente e o engine faz a 2ª chamada com a lista), não por regex nem por tool-calling. Requisito explícito do Hugo: queria decisão do modelo, não match de texto.
- `--tools`/MCP seguem desligados. O hardening do Sprint 7 (commit `1f07752b`, incidente 28/04 em que o TOM respondeu "preciso de permissão pra acessar o Supabase") não foi tocado.

**Renomeação no meio da execução:** a RPC nasceu como `get_team_links`; o Hugo apontou que a fonte é credencial, não uma tabela de links. Renomeada para `get_credenciais_publicas` (`ALTER FUNCTION ... RENAME`, que preservou os privilégios — verificado). Marker foi de `<<PEDIR_LINKS>>` para `<<PEDIR_CREDENCIAIS>>`.

**Implementação** (plano em `docs/superpowers/plans/2026-08-07-links-sistemas-tom.md`, executado com subagentes + review por task):

**Review final (Opus) achou 4 Important, todos corrigidos:**
- `logMarker` gravava `result: 'applied'`, que **não existe** no CHECK da tabela (`executed/rejected/skipped/redirected/fallback`). Como `logMarker` não lança, o caso de **sucesso** nunca seria registrado — só o de falha. Observabilidade nasceria invertida.
- Se a 2ª chamada à IA falhasse, os links já buscados eram descartados e o usuário recebia erro genérico. Agora `reply = bloco` antes da chamada: degrada para a lista crua.
- Mensagem mista ("me manda o link do CRM **e** anota tal coisa") faria o modelo emitir só o marker e perder a tarefa em silêncio — `TASK_UPDATE` é a ação mais usada do sistema. Instrução ajustada.
- Import morto e projeção explícita das colunas no serviço (defesa em profundidade).

**Estado:** deployado (SCP + `node --check` no VPS + `pm2 restart tom`, online). 3 credenciais marcadas visíveis (Anamnese, Chatwoot, LA Performance Report); checagem de segurança confirmou 0 credenciais com senha marcadas indevidamente.
