🔐 HMAC do webhook (Bloco A — código pronto, ativação adiada)

Middleware HMAC-SHA256 no /webhook com 3 modos:
- disabled: WEBHOOK_SECRET vazio (estado pré-Sprint 5, atual em dev)
- permissive: WEBHOOK_SECRET set + WEBHOOK_HMAC_ENFORCE != 'true'
  → valida e loga warning, mas processa (janela de transição).
- strict: WEBHOOK_HMAC_ENFORCE='true' → rejeita 401 quando ausente
  ou inválido.

Header configurável via WEBHOOK_SIG_HEADER (default
'x-webhook-signature'). Aceita formato 'sha256=<hex>' ou hex puro.

src/index.js:
- express.json verify callback expõe req.rawBody (Buffer cru
  preserva validação HMAC apesar do parsing JSON downstream).

src/webhook.js:
- verifyWebhookSignature(req): ler secret/header/enforce do env,
  computar HMAC, timingSafeEqual com a assinatura. Retorna
  {mode, ok, reason}.
- Chamado no início do handler, antes do dedupe. Strict + invalid
  → 401 antes do 200. Permissive + invalid → loga warning, segue.

Validação:
- 8 cenários em isolamento (disabled, missing-strict, malformed-strict,
  bad-strict, good-strict, bad-perm, good-perm, raw-hex-good).
- Smoke real permissive em prod com SECRET temporário, .env restaurado
  ao final.
- POST sem assinatura em mode disabled (estado atual) processa
  normalmente — sem regressão nas Sprints 0–4.

.env.example: WEBHOOK_HMAC_ENFORCE=false e WEBHOOK_SIG_HEADER=
x-webhook-signature documentados.
